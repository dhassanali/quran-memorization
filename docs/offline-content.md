# Offline Quran content: source and sync decision

Checked 2026-10-23 against the primary sources linked below. This note concerns the Arabic Quran text and page/word layout used by this static Vite application. The previous untracked `src/verses.json` had no verifiable source or license, so it was replaced before publication. The current search index is generated from the [official Tanzil Uthmani 1.1 download](https://tanzil.net/download/) with options `quranType=uthmani`, `outType=txt-2`, `marks=true`, `sajdah=true`, and `tatweel=true`. The downloaded source SHA-256 is `6933e133dd56db778c801bf738848454e43648105a151e8d84d86a7cae39ec5f`. `scripts/build-search-index.mjs` verifies that checksum and all 6,236 verse keys, copies verse strings unchanged into JSON, and embeds Tanzil's complete copyright notice. The notice is also distributed as `public/tanzil-text-NOTICE.txt` and linked in Settings.

## Quran Foundation (QF)

QF's [Developer Terms](https://api-docs.quran.foundation/legal/developer-terms/) (updated 2026-10-11, sections 2.2 and 3.1) permit display within an application, but prohibit selling, sublicensing, or redistributing QF content or raw API data without a separate written commercial license. A prepackaged database or build-time bundle is **not** authorized merely because Content Sync allows offline storage. A downloadable `verses.json` or a Vite bundle containing QF-derived text therefore needs its own verified permission before distribution. The terms expressly distinguish a developer-controlled backend serving the app's end-user experience from offering data as a dataset/feed/download; that distinction does not make a static JSON bundle safe by itself.

The same terms limit storage of content from ordinary API responses to one week. If the resource is offered through Content Sync, that is the **only** permitted way to obtain and maintain its offline copy. A Content Sync client must request its next sync at least every seven days whenever connectivity permits, apply all changes, and sync promptly after a longer outage; a previously synced copy may be used during that outage. These conditions apply to both backend and offline device copies. [Source: QF Developer Terms, section 3.1](https://api-docs.quran.foundation/legal/developer-terms/).

QF [Content Sync Getting Started](https://api-docs.quran.foundation/docs/tutorials/content-sync/getting-started/) lists `quran_core:1` for canonical verse and word data and `mushafs` resources for page mappings and positioned words. Its example filter `quran_core:1;mushafs:1` includes core plus Mushaf layout; word-level Uthmani text is in `mushafs:4`, so the app's exact QCF v2 presentation needs a resource and font compatibility check before migration. A snapshot is not a license to prepackage it. Production access is needed for the complete Quran; prelive contains only surahs 1 and 2 and cannot validate a 604-page reader.

The QF [Content API quickstart](https://api-docs.quran.foundation/docs/quickstart/) says Content APIs use a backend-held `client_secret`; browser/mobile clients must not embed it and their public SDK entry point is for User APIs, not Content APIs. This static Vite deployment therefore cannot safely implement the documented Content Sync calls on its own. It needs a small server endpoint/BFF with approved production credentials, or another documented QF-approved integration. The server should proxy authenticated sync and snapshot responses only to this application's client flow and should not expose a standalone public dataset/download endpoint.

### Implementable QF sync flow, if a backend is added

1. Register a backend app, obtain production Content API access, keep its secret server-side, and request a `content` token. Send `x-auth-token` and `x-client-id` from the backend. [QF quickstart](https://api-docs.quran.foundation/docs/quickstart/).
2. Bootstrap `quran_core:1` plus the verified Mushaf resource with `bootstrap=true`. Follow returned `next_page_url` until `has_more=false`; fetch each `snapshot_url`. Never construct cursors or mix environments. [Getting Started](https://api-docs.quran.foundation/docs/tutorials/content-sync/getting-started/).
3. Validate record IDs, page count and mappings, text fields, and a sample of verse/word boundaries before displaying or committing a snapshot in IndexedDB. Key rows by resource group, resource ID, record type, and record key. Apply a full replacement for `RESOURCE_CREATE`/`RESOURCE_INVALIDATE`, row mutations in sequence order, and removal for `RESOURCE_DELETE`. Store the **final-page** `next_sync_token` only after the changes are fully committed. [Client Flow](https://api-docs.quran.foundation/docs/tutorials/content-sync/client-flow/).
4. Run the next sync on launch and when online if the previous successful sync is approaching seven days; handle 401/429/network failures without discarding a valid offline copy. Trigger sync promptly when connectivity returns. Keep an explicit last-successful-sync time and filter-bound token in IndexedDB. [Getting Started](https://api-docs.quran.foundation/docs/tutorials/content-sync/getting-started/); [Client Flow](https://api-docs.quran.foundation/docs/tutorials/content-sync/client-flow/); [Developer Terms](https://api-docs.quran.foundation/legal/developer-terms/).

This is an architecture recommendation, not evidence that the current `https://api.quran.com/api/v4/verses/by_page/...` fetch and six-day cache in `src/quran.ts` is an authorized offline distribution flow. The current six-day cache may support short-lived online reads, but it must not be expanded into a permanent 604-page cache from ordinary responses.

## Independently redistributable alternative: Tanzil Arabic text

Tanzil's [Text License](https://tanzil.net/docs/Text_License) labels its Quran text CC BY 3.0 and explicitly permits **verbatim** copying and distribution. It prohibits changing the text, requires clear Tanzil attribution with a link to `tanzil.net`, and requires its full copyright notice in copies and files derived from or containing a substantial portion. The [official download page](https://tanzil.net/docs/download) identifies version 1.1 as the latest release, and its [updates page](https://tanzil.net/updates/) records the release date and textual corrections. These provide a source version and an update trail; record the downloaded artifact's SHA-256 in this repo as an additional integrity check. Do not treat Tanzil's translations as covered by this Arabic-text license; [their separate terms](https://tanzil.net/trans/) limit use to noncommercial purposes without further permission.

For a distributable offline Arabic **verse** reader, download the official Uthmani v1.1 text, retain its notice without altering the verse strings, validate 114 surahs and 6,236 verse keys, pin the source URL/version/hash, and show attribution plus the update link in the app. On future Tanzil releases, acquire the new official file, compare source hashes and verse keys, review the upstream change log, and ship a new app version. This is a practical inference from Tanzil's terms and versioned release process.

Tanzil's verse text is used for the local Arabic **search index** only. It does **not** by itself license QF/QCF page positions, QCF-specific glyph text, or the word IDs/line breaks this app needs for its current 604-page word-marking reader. Splitting Tanzil verses into words or applying existing QF layout requires separate fidelity and rights review because Tanzil prohibits changing the text and the layout/segmentation may be independently sourced. It is not a drop-in replacement for the page/word reader.

## Decision for this repository

The search index now has a verified redistributable source and in-app attribution under Tanzil's terms. The existing page/word experience still uses short-lived QF online reads; a permanent offline copy requires a backend-backed QF Content Sync path and verification of the exact Mushaf resource. If a backend and QF production access are unavailable, a separate Tanzil verse-level offline reader remains possible under its stated conditions, without claiming the QCF layout is covered by that text license.
